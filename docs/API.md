# 观潮后端接口文档（增量）

> 本文只记录**本轮改动涉及**的接口。全量接口列表见线上 Swagger：`https://www.blueakaiwu.cn/docs`

---

## 通用约定

**Base URL**：`https://www.blueakaiwu.cn/api/v1`

**统一响应体**（所有接口一致）：

```json
{ "code": 0, "message": "ok", "data": { }, "requestId": "..." }
```

`code` 为 `0` 表示成功；非 0 时 `message` 是给用户看的中文提示。

**分页**（带分页的接口，`data` 形状）：

```json
{ "list": [], "page": 1, "pageSize": 20, "total": 46 }
```

**身份**（按优先级）：

| 场景 | 传法 | 服务端归属 |
|---|---|---|
| 登录用户 | `Authorization: Bearer <accessToken>` | `user:{id}` |
| 游客 | `X-Client-Id: <设备标识>` | `client:{id}` |
| 都没有 | — | `client:guest` |

> ⚠️ **同一份数据必须用同一种身份读写**，否则两边对不上。
> 典型：观潮记录与图鉴点亮都用**游客身份**（前端 `auth: false`），
> 如果某个接口改成带 token，数据就会分别落到 `user:{id}` 和 `client:{id}` 下。

**主要错误码**：`400` 参数错误 / `401` 未登录 / `403` 无权限 / `404` 不存在 / `500` 服务器内部错误（`code: 50001`）

## 一、新增接口

### 1. 用户宝藏点位

用户自己上传的赶海点位。**与官方策展的 `spots` 是两张表**，不会混进公开的 `GET /spots` 列表。

#### `POST /spots` — 上传点位

**请求体**

```json
{ "name": "礁石湾", "address": "青岛市…", "lat": 36.08, "lng": 120.46, "note": "退潮有小螃蟹" }
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 点位名称，上限 64 字 |
| `lat` / `lng` | ✅ | 坐标，缺任一即报「请在地图上选择点位」 |
| `address` | | 上限 255 字 |
| `note` | | 备注，上限 1000 字 |
| `photoUrl` | | 图片地址，上限 255 字 |

**响应 `data`**

```json
{ "id": "usp_…", "name": "礁石湾", "address": "…", "lat": 36.08, "lng": 120.46,
  "note": "…", "photoUrl": "", "createdAt": "2026-10-03T22:17:56+08:00" }
```

**限制**：每个身份最多 100 个，超出报「上传的点位已达上限（100 个）」。

#### `GET /spots/mine` — 我上传的点位

无参数。按创建时间倒序。

```json
{ "list": [ { "id": "usp_…", "name": "…", "status": "pending",
              "reviewNote": "", "reviewedAt": "", "…": "…" } ] }
```

| 字段 | 说明 |
|---|---|
| `status` | 审核状态：`pending` 审核中 / `approved` 已通过 / `rejected` 未通过 |
| `reviewNote` | 驳回原因（`rejected` 时可能有） |
| `reviewedAt` | 审核日期 `YYYY-MM-DD`，未审核为空 |

> 「我的点位」页据此显示状态徽章。被驳回的投稿**不计入**每人 100 个的上传上限。

#### `DELETE /spots/{spot_id}` — 删除点位

只能删自己的。**别人的点位一律返回 `404 点位不存在`**（不区分「不存在」和「不是你的」，避免泄露信息）。

```json
{ "id": "usp_…" }
```

### 2. 图鉴点亮

#### `GET /encyclopedia/unlocked` — 我点亮的物种

给图鉴页做「已点亮 N / 总数」进度，以及判断哪些是「新获得」。

```json
{
  "speciesIds":    ["sp_abalone", "sp_agar"],
  "newSpeciesIds": ["sp_agar"],
  "litCount": 2,
  "totalCount": 46
}
```

| 字段 | 说明 |
|---|---|
| `speciesIds` | 已点亮的全部物种 id |
| `newSpeciesIds` | 其中**还没看过**的（前端据此加闪光与 NEW 角标） |
| `litCount` / `totalCount` | 进度条用 |

#### `POST /encyclopedia/seen` — 标记「看过了」

把已经展示给用户的「新获得」物种标记掉，之后它们只保留金边，不再闪光。

**请求体**

```json
{ "speciesIds": ["sp_agar"] }
```

**响应 `data`**：`{ "updated": 1 }`（本次真正更新了几行）

**幂等**：重复调用返回 `updated: 0`，不报错。传空数组也返回 `0`。

> 前端建议：**打开某个物种的详情页时**标记那一个，而不是图鉴列表一渲染就把整批标记掉 ——
> 后者会让用户还没看清就失去「新」的状态，效果也就看不到了。

### 3. 管理后台：审核宝藏点位

管理员审核用户上传的宝藏点位，通过后**发布成官方点位**（写进 `spots` 表），前台的
`GET /spots` 立刻可见，小程序无需改动。

**鉴权**：所有 `/admin/*` 接口都需要请求头 `X-Admin-Token`，值等于后端 `.env` 的
`ADMIN_TOKEN`。**未配置 `ADMIN_TOKEN` 时一律 401**（不会因为两边都是空串而放行）。
令牌只走请求头，不要用 query 传（会进访问日志）。

**页面**：浏览器打开 `<域名>/admin`，输入令牌即可操作（页面本身公开可加载，但无令牌调不动任何接口）。

#### `GET /admin/submissions` — 投稿列表

| 参数 | 默认 | 说明 |
|---|---|---|
| `status` | `pending` | `pending` / `approved` / `rejected` / `all` |
| `page` / `pageSize` | 1 / 20 | 分页，`pageSize` 上限 100 |

返回标准分页结构 `{ list, page, pageSize, total }`，每项含 `id / ownerId / name / address /
lat / lng / note / photoUrl / status / reviewNote / approvedSpotId / reviewedAt / createdAt`。

#### `POST /admin/submissions/{id}/approve` — 通过并发布

```json
{ "name": "礁石湾", "city": "青岛", "district": "崂山区",
  "description": "退潮有小螃蟹", "observeHint": "低潮前后两小时最佳" }
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `city` | ✅ | `spots.city` 非空且无默认值，必须由管理员确认 |
| 其余 | | 缺省时回退用户原值（`name`←投稿名，`observeHint`←`note`，`description`←`address`） |

- 通过后写入一条官方点位，`id` 形如 `spot_z_…`、`source="用户投稿"`、`reviewed_at=当天`、`heat` 默认 `40`。
- 重复通过 → `409 该投稿已通过审核`；缺坐标 → `400`；`city` 为空 → `400`。

#### `POST /admin/submissions/{id}/reject` — 驳回

```json
{ "reason": "位置不明确" }
```

`reason` 可空，存入 `reviewNote`，用户端在「我的点位」能看到。已通过的投稿不能驳回
（驳回不下架已发布的官方点位）→ `409`。

#### `GET /admin/stats` — 各状态计数

```json
{ "pending": 3, "approved": 12, "rejected": 1 }
```

## 二、已有接口的变更

### `GET /encyclopedia` — 图鉴列表

每个物种新增一个字段：

| 新增 | 类型 | 说明 |
|---|---|---|
| `lit` | bool | 调用方身份是否已点亮该物种 |

### `POST /ai/trash-guess` — 垃圾识别

响应新增垃圾总量档位：

| 新增 | 取值 | 说明 |
|---|---|---|
| `amount` | `none` / `little` / `some` / `much` | 无 / 少 / 中等 / 多 |
| `amountText` | `无` / `少` / `中等` / `多` | 直接展示用 |

**判断依据是件数**：1~2 件＝少，3~5 件＝中等，6 件以上或成片堆积＝多。
单件体积大（比如一个装满的垃圾袋）**仍算少**。

### `POST /watch/sessions/{session_id}/species` — 往观潮里加一条发现

响应新增：

| 字段 | 说明 |
|---|---|
| `newlyLitSpecies` | 本次**新点亮**的图鉴物种 `{id, name, coverUrl}`；没有新点亮则为 `null` |
| `trashDailyLimit` | 为 `true` 表示这条被拒（垃圾当天已经记过一次） |

**行为变更**：`kind: "trash"`（垃圾）**每天只允许记一次**；`kind: "species"`（生物）不受限制。
被拒时不会写入，直接返回 `trashDailyLimit: true`。

### `POST /watch/sessions/{session_id}/end` — 结束观潮

**行为变更**：合并请求体里离线条目时，垃圾同样**每天只保留一条**。
（离线记的条目是在这一步才合并进来的，不在这里也拦一道的话，单条写入那边的限制等于白设。）

### `GET /watch/records` — 观潮记录列表

每条新增：

| 字段 | 说明 |
|---|---|
| `seq` | 观潮编号，按开始时间从早到晚编号，从 1 起 |

### `GET /watch/records/{record_id}` — 观潮记录详情

在上面的基础上再加：

| 字段 | 示例 | 说明 |
|---|---|---|
| `dateText` | `周六.10.03` | 日期写法 |
| `timeText` | `14:00-15:30` | 时间段 |
| `tempText` | `24℃` | ⚠️ 见下方说明 |
| `weatherText` | `多云` | ⚠️ 见下方说明 |
| `tideText` | `-1.1 米` | 潮高，替代「深度」。取不到时为空串 |

> ⚠️ **温度 / 天气目前是占位数据**：`get_weather` 是写死的 `{"text": "多云", "tempC": 24}`，
> **每条记录都会显示「多云 24℃」**。接真实天气接口后这里会自动变真，前端不用改。
>
> ⚠️ **`tideText` 可能是负数**：潮汐服务的原始值以平均海平面为基准，低潮时为负。
> 直接展示成「潮高 -1.1 米」用户会困惑，建议前端改成「退潮中」或「今日 0.3~3.8 米」这类说法。

### `GET /spots` — 点位列表（本轮数据大改）

**点位从 4 个增至 42 个**（41 个青岛 + 1 个威海），数据来源为团队整理的
《青岛赶海点位热度排名》。

**每项新增字段**：

| 新增 | 说明 |
|---|---|
| `district` | 所属区（`崂山区` / `黄岛区` / `市南区` / `即墨区` / `荣成市`） |

**热度值改为按排名档位映射**（原来是几个手工值）：

| 档位 | heat |
|---|---|
| 极热门 | 100 |
| 热门 | 85 |
| 较热门 | 70 |
| 一般 | 55 |
| 其他（平列） | 40 |

列表仍按 `heat DESC` 排序，所以**排在前面的就是最热门的点位**。

**坐标**：41 个点位已用高德地理编码补全。`青岛·顾家岛码头` **故意留空** ——
高德没搜到该地名，返回的最近结果是「鱼鸣嘴码头」，而鱼鸣嘴本身已是另一个点位，
两者相距仅 233 米，写进去就是错数据。

### `POST /ai/tide-advice` — 出行建议（本轮改动最大）

原来是「传点位 id、返回一大段 AI 文案」。现在前端改成**传坐标**，后端返回
**推荐时间 / 离场时间 / 一个推荐地点**。

**请求体**

```json
{ "lat": 36.062, "lng": 120.319, "date": "2026-10-04" }
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `lat` / `lng` | ✅ | 用户当前位置。**推荐传这个** |
| `date` | | 日期，默认今天 |
| `spotId` | | 兼容老调用：指定点位而不是按坐标找 |

两种定位方式二选一：给了 `lat`/`lng` 就按坐标找，否则用 `spotId`。

**响应新增三个字段**（原有字段都保留，未破坏兼容）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `bestTimeFrom` | string \| null | **推荐时间**，如 `15:20` |
| `bestTimeTo` | string \| null | **离场时间**，如 `17:40` |
| `recommendedSpot` | object \| null | **推荐地点** |

`recommendedSpot` 的结构：

```json
{
  "id": "spot_qd_shilaoren",
  "name": "青岛·石老人",
  "district": "崂山区",
  "heat": 100,
  "distanceM": 11200,
  "distanceText": "11.2 公里"
}
```

**不适合赶海时，这三个字段都是 `null`**，看 `suitableNow: false` 即可
（前端显示「不适合赶海」）。

**推荐地点的选法**：在离用户**最近的 5 个点位**里挑**热度最高**的那个。
只推最近一个容易推到冷门点，只推最热又可能离得很远 —— 取「最近的几个」再按
热度选，兼顾近和值得去。

> ⚠️ **已知问题**：`bestTimeFrom` 可能落在**凌晨**。
> 它取的是「下一个低潮」，当天低潮都过去了就会取次日第一个低潮，
> 实测出现过 `01:36`。对亲子场景不可用，**待定是否限制为白天时段（06:00~20:00）**。

## 三、行为变更（接口签名没变，但语义变了）

### 签到幂等

`POST /records/checkin` 在并发重复提交时**只会写入一条**记录。

服务端在 `report_checkins` 表上加了唯一键 `(owner_id, checkin_date, session_id)`。
并发下被唯一键拦下的请求会返回**已存在的那条**，并带 `alreadyChecked: true`，不会报 500。

实测：修复前 5 轮 × 20 并发有 4 轮写出重复记录（复现率 80%），修复后 0%。

### AI 物种识别的地理过滤

`POST /ai/species-guess` 不再因为「用户不在海边」就把**所有**候选过滤掉。

原来用户离最近赶海点超过阈值时，命中图鉴的候选会被全部丢弃，最终回一句
「这不是常见的赶海生物」—— 等于当面否认用户拍到的生物。
现在地理过滤只在**还有别的可选**时生效；全被滤掉时会兜底保留概率最高的那个。

## 四、前端接入注意事项

**① 图鉴相关接口必须同为游客身份**

`GET /encyclopedia` / `GET /encyclopedia/unlocked` / `POST /encyclopedia/seen`
与写入点亮的 `POST /watch/sessions/{id}/species` **都走 `auth: false`**（`client:{id}`）。

若把图鉴那三个改成带 token，点亮会记在 `user:{id}` 下、列表却按 `client:{id}` 查，**图鉴将永远点不亮**。

**② 垃圾量的两级兜底**

观潮记录里存的 `amount` 是当时 AI 的判断。**老记录没有这个字段**，前端按件数兜底
（规则与后端一致：≤2 少、≤5 中等、更多为多）。

**③ 本地记录与线上记录**

观潮记录有本地缓存（离线也能记）。本地记录没有 `seq` / `dateText` 等字段，
渲染时按空值处理即可，不要假定一定有。

**④ ✅ 每个点位的潮汐已各自独立（原「占位」问题已解决）**

潮汐不是调第三方接口，而是用 **FES2022b 中国近海版天文潮模型离线计算**的。
每个点位的调和常数由 `tools/build_spot_harmonics.py` 按其经纬度从 1/30° 网格
取最近有效格点生成，落在 `app/services/spot_harmonics.py`（**自动生成，勿手改**）。

- 42 个点位**全部**有自己的常数（顾家岛码头无坐标，借用一浴的）；
- 相隔几十公里的点位，潮高与低潮时刻**不再相同**；
- 用户投稿过审后新增的点位不在表里，`tide_predict.resolve_spot` 会**就近兜底**
  到最近的有点位；想精确就把它补进 `seed.py` 的 `SPOTS` 再重跑生成脚本。

数值口径：结果是**相对 FES2022b 模型平均面**的潮位偏差（米），**不是**海图基准上的
绝对潮高，低潮可为负。显示相对变化没问题，别当绝对海拔用。
